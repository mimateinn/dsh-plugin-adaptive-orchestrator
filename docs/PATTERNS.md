# UI and Visual Patterns

- Use English for all plugin UI copy.
- The global enable switch is the single primary control; disabling it must visibly restore ordinary DSH behavior.
- Never imply that the captain can be upgraded automatically.
- Show routing explanations as concise reason codes plus human-readable detail, never prompt content.
- Sensitive mode must display its selected model allowlist and fail-closed state explicitly.
- Use the plugin identity colors: graphite core, cyan-to-blue routing accents, and neutral surfaces.
- Use the central hexagon for the fixed captain, connected nodes for workers, and the partial arc for quota/reset pressure.
- Every interactive setting needs a stable test ID, keyboard access, visible focus, and an actionable error state.
- Prefer inline status for persistent compatibility/quota conditions; reserve toasts for completed transient actions.
- Light and dark themes must preserve icon and status contrast without provider-brand colors.
